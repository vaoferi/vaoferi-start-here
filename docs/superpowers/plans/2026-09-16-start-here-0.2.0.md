# Vaoferi Start Here 0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release Vaoferi Start Here 0.2.0 with an explicit project-adaptation lifecycle for legacy/existing repositories, stronger multilingual text hygiene, and a pinned Vaoferi Design Skill 0.4.1 containing CSS ownership/dependency guardrails.

**Architecture:** Keep `AGENTS.md` compact and universal. Existing/new repo discovery stays in `vaoferi-bootstrap`; reconciliation of pre-existing project rules/docs becomes a separate lazy-loaded `vaoferi-project-adaptation` skill. Design-specific source ownership remains in the separate `vaoferi-design-skill` repository and is vendored into Start Here by exact commit/hash.

**Tech Stack:** Markdown skills, Python 3.11+ stdlib, `unittest`, SHA-256 manifest/vendor lock, GitHub Actions.

**Spec:** User-approved 2026-09-16 design in chat, extending `vaoferi/nlm.help/docs/superpowers/specs/2026-09-15-vaoferi-start-here-design.md`.

## Global Constraints

- No silent rule loss during project adaptation.
- `PROJECT_RULES.md`, project docs, tests and design facts remain project-owned unless explicitly classified universal.
- Meaningful conflicts require owner decision; never silently choose one active instruction over another.
- Cleanup happens only after destination + parity + reference verification.
- Existing product/design patterns remain authoritative unless redesign is explicitly requested.
- Local gitignored secret stores remain allowed; this release must not regress the practical `.env` policy.
- Start Here version becomes `0.2.0`; Design Skill becomes `0.4.1`.
